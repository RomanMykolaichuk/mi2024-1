3 · PYTHON LAB 2

Описова статистика: дивимося не лише на середнє

Для skewed distributions і рідкісних подій медіана та перцентилі часто інформативніші за середнє.

Describe + grouped profilepandas
print(
    df[["delay_min", "confidence"]]
      .describe(percentiles=[0.5, 0.75, 0.9, 0.95])
      .round(2)
)

by_source = (
    df.groupby("source")
      .agg(
          events=("event_id", "count"),
          median_delay=("delay_min", "median"),
          mean_confidence=("confidence", "mean"),
          missing_confidence=("confidence", lambda s: s.isna().sum()),
      )
      .round(2)
)
print(by_source)

Питання до результату

  • Чи сильно відрізняється median від mean?
  • Наскільки p90/p95 віддалені від типового значення?
  • Чи відрізняються джерела за delay або missingness?
  • Чи може різниця бути наслідком різного обсягу спостережень?

5 · PYTHON LAB 4

Кореляція — це сигнал до перевірки, а не доказ причини

У невеликому dataset коефіцієнт кореляції легко переоцінити. Він має бути частиною evidence-пакета разом із графіком, контекстом і перевіркою confounders.

Numeric relationshipspandas
numeric = df[["delay_min", "confidence"]]

corr = numeric.corr(numeric_only=True).round(3)
print(corr)

# Додатково порівняйте групи, а не лише global correlation
print(
    df.groupby("event_type")
      .agg(
          median_delay=("delay_min", "median"),
          mean_confidence=("confidence", "mean")
      )
      .round(2)
)

Правильне формулювання

«У вибірці спостерігається слабкий/помірний/сильний статистичний зв’язок» — коректніше, ніж «confidence впливає на delay».

Перевірка: чи не пояснюється global relationship різними event types або sources?

6 · PYTHON LAB 5

Anomaly detection має завершуватися списком для перевірки

EDA знаходить кандидата на аномалію; предметна верифікація вирішує, чи це помилка, рідкісна подія або окремий режим процесу.

IQR anomaly reviewpandas
q1 = df["delay_min"].quantile(0.25)
q3 = df["delay_min"].quantile(0.75)
iqr = q3 - q1
upper = q3 + 1.5 * iqr

flagged = df.loc[
    df["delay_min"].gt(upper),
    ["event_id", "source", "sector", "event_type", "delay_min", "timestamp"]
].sort_values("delay_min", ascending=False)

print(flagged)

Наступна дія

Для кожного flagged row поставте питання: чи підтверджується provenance, чи є технічна причина, чи траплялися подібні випадки, як рядок впливає на метрики?

Не робіть: автоматичне видалення всіх flagged rows без перевірки.

WHY IT MATTERS FOR THE ANALYST

EDA має завершуватися рішеннями про подальшу обробку

Графік сам по собі не є висновком. Результат EDA — перелік проблем даних, перевірених закономірностей, невизначеностей і гіпотез, які визначають наступні кроки.

7 · TEAM MISSION

Зберіть профіль даних

Використайте інтерактивну місію як структуру, але підкріпіть кожен пункт результатом Python-команди або графіка.

Формат фінального EDA-висновку

  1. Quality: 1–2 конкретні проблеми з кількісним evidence.
  2. Distribution: що є типовим і що формує хвіст розподілу.
  3. Groups: одна перевірена різниця між source/event type.
  4. Anomaly: які записи потребують предметної верифікації.
  5. Next action: яке preprocessing-рішення або додаткову перевірку виконати далі.
