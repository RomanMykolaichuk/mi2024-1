ТЕМА 2 · ЗАНЯТТЯ 5 · RELATIONAL DATABASE / SQL MISSION

Від двох таблиць до аналітичного запиту

Практичне заняття перетворює схему БД на послідовність аналітичних дій: визначити PK/FK, створити зв’язок, виконати SELECT, WHERE, JOIN, GROUP BY, ORDER BY і підзапит — та пояснити, що саме отриманий результат означає для аналітика.

ANALYTICS PIPELINE

SQL починається не із запиту, а зі структури даних

На цьому занятті ми працюємо на етапі зберігання, але результат одразу переходить у аналіз.

1 · RELATIONAL SCHEMA BUILDER

Визначте PRIMARY KEY і FOREIGN KEY

Оберіть один із шести варіантів вихідного практичного завдання. Для кожного визначте ключ довідникової таблиці та поле зв’язку в основній таблиці.

WHY IT MATTERS FOR THE ANALYST

Неправильний зв’язок таблиць дає формально правильний, але змістовно хибний результат

JOIN працює коректно лише тоді, коли ключі відображають реальний зв’язок сутностей. Тому проєктування схеми — частина аналітичного мислення, а не лише робота адміністратора бази даних.
